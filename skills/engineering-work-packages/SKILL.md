# Engineering Work Packages

A work package is the unit of engineering delivery: bounded scope, listed deliverables, controlled documents, checked work, clean handover.

## When to use
- Kicking off any engineering task beyond a trivial note (studies, replacements, upgrades).
- Tracking deliverables across a shutdown, retrofit, or capital job.
- Handover prep (as-built, records, spares).

## Method
1. **Define the package**: objective; scope (in/out); deliverables list (calc package, datasheets, drawings, test plans, procedures, BOM, reports); standards and site rules; interfaces; budget link; schedule; acceptance criteria.
2. **Document control**: numbering/naming convention; revisions (rev letter + reason); status flow (Draft → For Review → For Approval → For Construction/As-Built); revision-history table on every controlled document.
3. **Check discipline**: every calculation independently checked (designer ≠ checker); red-line/back-check process; sign-off blocks (prepared/reviewed/approved).
4. **Transmittals**: log what was issued, to whom, which revision, when — and the return status; nothing is "issued" verbally.
5. **Delivery quality**: each document states purpose, inputs, assumptions, standards cited, units, results, and check signature. Assumptions explicit, never embedded.
6. **Handover**: as-built marked, O&M references, spares list, test-records pointer, training notes; close-out checklist signed.

## Quality gates
- [ ] Deliverables list agreed and complete (or gaps documented).
- [ ] Checks signed; revisions controlled with history.
- [ ] Transmittal log current; no uncontrolled copies floating.
- [ ] Handover pack complete at close-out.

## Red lines
- No unapproved revision used "for construction"; no untraceable changes; superseded versions retained (marked), never deleted.
